# #77 — stt: multilingual interviews — `[stt].language = "auto"` detects the language per utterance and a multilingual whisper model translates every lane to English

Labels: `size:M, model:opus, m2, lane:stt, backlog`

Proposed 2026-09-26 as a backlog item. Brainstorm for the next iteration: an option for interviews held in another language. Decisions taken with the user: translation happens inside whisper (task = translate), so the detector, prompts, sections and UI stay English and unchanged; the language is auto-detected per utterance; the Approach stays English. A different model is required: the `.en` models cannot translate, so `small` (multilingual, the same 488 MB class as `small.en`) is the CPU choice and `large-v3-turbo` the GPU one — and `large-v3-turbo` (1.6 GB) does not fit beside the Ollama model at `num_ctx = 8192` (#61 measured 1.2–1.3 GB free), so on the dev box it is `small` on the GPU lane or on the CPU.

## Goal
Let a call in a language other than English go through the same pipeline: a multilingual whisper model detects the language of each utterance and emits English text for both lanes, so questions are detected, answered and shown exactly as for an English call, with the detected language visible (SPEC § Transcription and question detection; § Data, config and privacy).

## Size / Model / Turns
M | Opus | 45   (from docs/PROCESS.md; labels must match). The non-English fixture is inside this issue like #63's continuous fixture; if the budget is tight, split it out first as an S fixture issue (like #23) that this one depends on.

## Scope
- `crates/dmn-stt`: the model registry gains the multilingual files `tiny`, `base`, `small`, `medium` (`ggml-<name>.bin`, sizes and sha256 from the HF tree API as #8 recorded them; `large-v3-turbo` is already multilingual) and `Model::is_english_only()`. `Transcriber` takes a `Language { English, Auto, Fixed(code) }`: `English` keeps today's `set_language(Some("en"))` path bit for bit; `Auto` and `Fixed` set `set_translate(true)` and, for `Auto`, detect the language on the utterance's first inference and pin it for that utterance's later partials and final (detection on every partial would cost on the 437-of-492 partial inferences #16 measured); the segment carries `language: Option<String>` (ISO 639-1 from whisper's lang id). Loading a `.en` model with `Auto` / `Fixed` is `SttError::ModelIsEnglishOnly` naming the fix. `audio_ctx_for` was tuned on `small.en` (transcriber.rs:75-78): re-measure it on `small` with `dmn bench` and keep the tuning per model family. The prompt (`last_final`, worker.rs:208) stays: in translate mode the last final is English, which is the decoder's output language.
- `crates/dmn-core` config: `[stt].language = "en" | "auto" | "<iso 639-1>"` (default `"en"`; `deny_unknown_fields`, the SPEC-example key count becomes 27, the TEMPLATE comment names `small` for non-English). `--language` on `dmn run`, `dmn replay` and `dmn bench` like `--vad` / `--device`. `dmn doctor`: the whisper model check refuses a `.en` model when `language != "en"` ("set [stt].model to small, medium or large-v3-turbo, or language to en"); `--fetch small|medium|tiny|base` downloads the multilingual files. `dmn config show` unchanged.
- `dmn-session` / `dmn-store`: `Segment` gains `language`; the next schema version adds `segments.language TEXT NULL` (v8 if this lands before #76, else v9); the JSONL export and replay `--json` carry it; the recorder writes it.
- `apps/dmn-cli`: the TUI status line shows the last detected language when it is not `en` (`stt gpu · es`); transcript lines are the English text (whisper's translate task produces only English, so no original is shown). Replay's header names the language mode; the headless summary counts utterances per detected language.
- Fixture: `testdata/<lang>/` (Spanish first: well supported by whisper, and Piper has `es_ES` / `es_MX` voices; choose a voice whose licence allows redistribution, as testdata/README.md does for English) generated by `tools/fixtures/generate.py` from a script whose turns carry the spoken text plus an `english` reference; `questions.json` holds the English reference so `eval/run.py`'s similarity match (≥ 0.35 over words) and `dmn bench`'s WER score the translated output; `eval/run.py` gains the fixture and a `--language` pass-through; shipped as release `fixtures-v3` with its sha256 file and `just fixtures-fetch`.
- Docs: SPEC § Transcription (language mode, model requirement, detect-then-pin), the `[stt]` example, the STT model row ("`small` for non-English"), § Data (segment language); docs/DEPENDENCIES.md unchanged (whisper-rs 0.16 already exposes `set_translate`, `set_detect_language` and the lang id); testdata/README.md voices table; docs/issues/README.md line.
Out of scope: answering in the interview's language (the user chose English output), showing the original-language transcript, per-language detector cues, LLM-side translation, the echo guard and the BM25 stop list (both operate on the English output), everything else including later issues.

## Acceptance
- [ ] `[stt].language = "en"` (the default) is unchanged: the existing fixture eval numbers and `cargo test -p dmn-stt` are identical before and after
- [ ] With `language = "auto"` and model `small`, the Spanish fixture reaches recall ≥ 0.85 and precision ≥ 0.8 (the M1 bar; translated text is why it is not the M2 0.9, stated in the SPEC with the measured numbers) and every question's English text matches its reference at similarity ≥ 0.35
- [ ] Every segment of the Spanish fixture is detected as `es` (replay `--json` `language` field); the English fixtures under `language = "auto"` are detected as `en` and lose at most 0.05 recall against `small.en` (measured and recorded in the SPEC, with the `en` default kept because of it)
- [ ] Fixture p50 question-end → Approach with `small`, `auto`, CPU stays ≤ 2.0 s (M1 budget); the detection cost per utterance is measured and recorded
- [ ] `dmn doctor` with a `.en` model and `language = "auto"` fails the whisper check with a one-line fix; `dmn doctor --fetch small` downloads and size-checks the multilingual model
- [ ] The TUI status line shows the detected language when it is not `en` (snapshot test); the segment language survives the store, the export and the action log
- [ ] `just check`, `just test` and `just lint` green
